# Research result

**Status: Partial**

High-end, prompt-heavy Claude Code setups are a virtual engineering team sequenced Think → Plan → Build → Review → Test → Ship → Reflect, not a flat bag of snippets. [S7] Mid-August 2026 shipped that model as installable plugins and lifecycle suites; `/scrape` is the read-only Browser Data Extractor—first matching-intent call prototypes via `$B` (~30s), later matches run a codified browser-skill in ~200ms, and `/skillify` persists the prototype. [S2] Recreate the family as several trees: one control coding catalog, generated host projections, a four-skill conversational subset, and a sibling memory repo, routed from a short CLAUDE.md so procedures load only when invoked. [S10][S19] With `./setup --prefix`, `/scrape` is `/gstack-scrape`; keep that namespace when other packs are installed and do not hand-copy skill bodies into the project. [S20][S21]

### Prompt family by tree

**Control coding catalog** (one directory per skill; gstack clone + `./setup`). Role map: `/office-hours` (YC Office Hours), `/plan-ceo-review` (CEO/Founder), `/plan-eng-review` (Eng Manager), designer review that catches AI slop, `/review` (Staff Engineer), `/qa` (QA Lead), `/cso` (Chief Security Officer), `/ship` (Release Engineer). Pair `/scrape` → `/skillify` for browser extraction; use `/browse` instead of `mcp__claude-in-chrome__*` tools. Inside a skill, do not inline everything: preamble tiers T1 (browse / setup-cookies / benchmark) through T4 (ship / review / qa / design-review / land-deploy) gate shared boilerplate; office-hours is a decision-tree that reads `sections/` only when needed; `/review` Step 4.5 dispatches `review/specialists/{testing,maintainability,security,performance,data-migration,api-contract,red-team}.md` from diff scope; `ship/sections/` holds adversarial, changelog, greptile, plan-completion, pr-body, review-army, and tests. [S9]

**Official session gates** (host built-ins, not a second copy of `/review`): `/plan` before a large change; `/context` and `/compact` when the window fills; `/code-review` (alias `/review`) on the current diff; `/security-review` on branch vs origin default for injection, auth, and data exposure. [S12]

**Always-on versus optional commands** (Addy Osmani pack; do not load all 24 skills every session). Eight lifecycle jobs: `/spec` (define), `/plan` (atomic tasks, read-only, writes `tasks/plan.md`), `/build` (one TDD slice then stop; `/build auto` only on unambiguous approve/go/yes), `/test` (tests are proof), `/review` (code health), `/webperf` (measure first), `/code-simplify` (clarity), `/ship` (faster is safer). Always-on from day one: test-driven-development, git-workflow-and-versioning, security-and-hardening, documentation-and-adrs. Grow-into: frontend-ui-engineering and browser-testing-with-devtools on first UI work; performance-optimization when requirements appear. Brownfield phase 1 starts with context-engineering. Steady loop: `/spec` → `/plan` → `/build` → `/review` → `/ship`. [S13][S14][S15]

**Mandatory Superpowers workflows** (official marketplace: `/plugin install superpowers@claude-plugins-official`). Skills auto-trigger. Partition by SDLC, live tree flat under `skills/<name>/`: Testing (`test-driven-development` — no production code without a failing test first; exceptions only for throwaway prototypes, generated code, config, and only after asking); Debugging (`systematic-debugging`, `verification-before-completion`); Collaboration (`brainstorming` before any creative work, `writing-plans` when a spec exists and before touching code, `executing-plans`, requesting/receiving-code-review after each subagent task, after major features, and before merge, `worktrees`, `finishing-a-development-branch`, `subagent-driven-development`); Meta (`writing-skills`, `using-superpowers`). New skills are generally not accepted in-repo; evals live in `prime-radiant-inc/superpowers-evals`. The archived extras repo used taxonomy folders (architecture, collaboration, debugging, meta, problem-solving, research, testing) cloned to `~/.config/superpowers/skills/`. [S11][S16]

**Sibling trees, not extra folders in the coding repo.** OpenClaw is a methodology source: native skills are `office-hours`, `ceo-review`, `investigate`, and `retro` under `openclaw/skills/` — no browse, telemetry, or preamble, and no port of the coding skills. GBrain is a separate repo; its resolver defers brainstorm / CEO-review / debug / retro to GStack when installed. Host adapters are generated projections from `hosts/*.ts`, not separately authored copies: Claude `~/.claude/skills/gstack`, Codex `~/.codex/skills/gstack-*` plus `.agents/skills/gstack`, OpenCode `~/.config/opencode/skills/gstack-*`, and the same pattern for Cursor, Factory, Slate, Kiro, Hermes, and GBrain. Mid-August plugins and the PM lifecycle zip stay optional add-on trees; do not merge those bodies into the control catalog.

### Catalog unit and project wiring

The portable unit is a directory whose `SKILL.md` has required YAML `name` (≤64 chars, lowercase letters/numbers/hyphens, matches the parent dir) and `description` (≤1024 chars, what and when), optional `scripts/`, `references/`, `assets/`, and a body kept under 500 lines with detail in referenced files. [S17] On Claude Code, store slash catalogs as skills at `~/.claude/skills/<name>/SKILL.md` or `.claude/skills/<name>/SKILL.md`; `.claude/commands/*.md` still works but a same-named skill wins; a skill directory may be a symlink. [S18] CLAUDE.md is always-on memory (project `./CLAUDE.md` or `./.claude/CLAUDE.md`, user `~/.claude/CLAUDE.md`, target &lt;200 lines) for facts, build commands, and always-do rules—not the catalog; multi-step procedures move into skills so they load only when used. [S19]

gstack’s working tree is one top-level directory per skill (`SKILL.md.tmpl` → generated `SKILL.md`). Setup creates real host-facing directories whose `SKILL.md` is a symlink so Claude discovers `/review` or `/gstack-review`, not `/gstack/review`. Install is `git clone … ~/.claude/skills/gstack && ./setup`; project vendoring is deprecated in favor of global install plus `./setup --team`. [S8][S20] Project convention is a `## gstack` routing list (optional `## Skill routing`), not vendored bodies; team-init writes that block, required mode adds a PreToolUse hook that denies work unless `~/.claude/skills/gstack/bin` exists, and a vendored `.claude/skills/gstack` tree is removed and gitignored. Uninstall does not edit CLAUDE.md—remove those sections by hand. [S21][S22]
